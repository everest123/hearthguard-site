What you're trusting

My Maestro AI is built to keep agents within the limits you set. Still, a team of agents with real access depends on many moving parts, and each one is part of your security. This is what you're trusting when you run it.

This computer

Your Maestro runs on your computer and listens only there, unless you turn on remote access, which needs two-factor. Keeping it safe also depends on that computer: its updates, passwords and disk encryption, and who else can use it. Agents that run directly on the computer can do what its user account can do; others run in a container that sees only the folders you grant.

Your AI models

A cloud model (Claude, GPT, Gemini and others) receives what an agent sends it: your messages, the conversation so far, the files and pages it works on, and tool results. The provider handles them under its own terms. A model running on your computer processes requests there, though tools and connected accounts can still send information out.

What you connect

Email, calendars, chat apps, wallets and other accounts give agents more reach. Each connection is another path for information to come in or go out, and an agent can act through it.

What agents read

Web pages, emails and documents can hide instructions meant to steer an agent. Agents are told to treat what they read as information, and your Maestro checks the actions they take, but agents can still be misled and no check catches everything.

The software

My Maestro AI gets security reviews and fixes, but like any software it can still have flaws. Fixes arrive as updates that you choose to install. From version 5.7.0, your Maestro tells you when an update is ready and marks the ones that fix security problems.

How we recommend using it

  • For you and people you trust: give accounts only to people you'd trust with the computer itself.
  • With agents you trust, each with only the folders, accounts and tools it needs.
  • Without anything you wouldn't be comfortable having shared with a third party or exposed in a breach.
  • With backups of what matters, approval cards on for the actions you want to check first, and limits on anything that spends money: agents can make mistakes even when nobody is attacking them.
  • Kept up to date, with two-factor on, and reached from other devices only through Tailscale.

Your data stays home

Conversations, memories, records and files live on your own machine, in plain files and SQLite you can read and back up yourself. Processing follows the model you choose: a hosted model sees the turns it handles, under its provider's terms, and a local model sends nothing off the machine. Agents that handle sensitive matters can be kept on local models.

  • Listens only on the machine itself until you decide otherwise, and opening it to a network requires an administrator with two-factor authentication.
  • Wallet keys and connector credentials are encrypted at rest and lock again after a period of inactivity.
  • No telemetry. Updates happen when you press the button, from the channel you choose.

Every action checked

Agents act through tools, and every tool call passes a policy you set before it runs.

A policy gate on every action

Each tool call is classified as a read, a write, a send, an administrative, destructive or money action, and checked against the agent's role and your overrides. One switch halts every agent at once.

Approval when you want it

Choose which kinds of action always wait for you, such as anything destructive or anything that spends money, and approve them from a card on your desktop or phone.

Root, by your hand only

Administrator rights on the machine are reserved for the lead agent, unless you lend another agent root for a set time. Your Maestro logs the root commands it sees. For added protection, don't let the computer account your Maestro runs under use administrator rights without a password (password-free sudo).

Money behind a firewall

Trading wallets sign only within the limits and the address book you set, and anything that moves money can be set to wait for your approval.

Contained by design

Each agent sees what it needs, and nothing more.

Sandboxed agents

An agent's shell can run inside its own container, which mounts only its workspace and the folders you grant, and its file tools check where symbolic links lead before following them.

Private family members

Members' agents run in containers, with access controls designed to keep each member's agents and files apart, and members get only the permissions you grant them. Sharing an agent with a member lets them use and change it and see its files, so share only with members you trust.

Scoped tokens for scripts

A script gets a token for exactly what it needs, usable only from the hub's own machine unless you allow more, with an expiry date and one-click revoke.

Two-factor sign-in

Accounts sign in with a password and an authenticator code, and the security check flags any account that has not set it up.

It watches itself

Security is not a setting you choose once. The hub checks itself every day.

A nightly security check

Every night the hub reviews its accounts and two-factor, network exposure, file permissions, agent permissions, tokens and open services, and tells you exactly what to fix. It runs from a terminal too, even when the hub is down.

A record of everything

Every turn is kept in the transcript, every root command and permission change is logged, and every turn is costed in the ledger. You can always see who did what, and when.
