Security

Powerful agents. Firm boundaries.

Your agents do real work on real systems. My Maestro AI makes sure they do only the work you allow, on hardware you own, and tells you the moment anything needs attention.

Your dataEvery action checkedContainedSelf-checkingLicense

Your data stays home

Conversations, memories, records and files live on your own machine, in plain files and SQLite you can read and back up yourself. Processing follows the model you choose: a hosted model sees the turns it handles, under its provider's terms, and a local model sends nothing off the machine. Agents that handle sensitive matters can be kept on local models.

  • Listens only on the machine itself until you decide otherwise, and opening it to a network requires an administrator with two-factor authentication.
  • Wallet keys and connector credentials are encrypted at rest and lock again after a period of inactivity.
  • No telemetry. Updates happen when you press the button, from the channel you choose.

Every action checked

Agents act through tools, and every tool call passes a policy you set before it runs.

A policy gate on every action

Each tool call is classified as a read, a write, a send, an administrative, destructive or money action, and checked against the agent's role and your overrides. One switch halts every agent at once.

Approval when you want it

Choose which kinds of action always wait for you, such as anything destructive or anything that spends money, and approve them from a card on your desktop or phone.

Root, by your hand only

Administrator rights on the machine belong to the lead agent alone. You can lend another agent root for a set time, and every root command is logged.

Money behind a firewall

Trading wallets sign only within the limits and the address book you set, and anything that moves money can be set to wait for your approval.

Contained by design

Each agent sees what it needs, and nothing more.

Sandboxed agents

An agent's shell and files can run inside its own container, which sees only its workspace and the folders you grant. Sign-in credentials can stay outside the container entirely.

Private family members

Members' agents run in containers and cannot reach another member's agents or files. Members get only the permissions you grant them.

Scoped tokens for scripts

A script gets a token for exactly what it needs, usable only from the hub's own machine unless you allow more, with an expiry date and one-click revoke.

Two-factor sign-in

Accounts sign in with a password and an authenticator code, and the security check flags any account that has not set it up.

It watches itself

Security is not a setting you choose once. The hub checks itself every day.

A nightly security check

Every night the hub reviews its accounts and two-factor, network exposure, file permissions, agent permissions, tokens and open services, and tells you exactly what to fix. It runs from a terminal too, even when the hub is down.

A record of everything

Every turn is kept in the transcript, every root command and permission change is logged, and every turn is costed in the ledger. You can always see who did what, and when.
